# 개요
---

> STT / TTS 기반의 영어 회화 평가 도구

해당 프로젝트는 **2일 사내 해커톤**으로 진행한다. 운영·장애 대응보다 영어 회화 평가의 핵심 흐름을 구현하는 데 집중하며, 기능 범위는 제한하고 핵심 데이터 흐름을 명확하게 설계한다.

**플랫폼** : 웹(Web)

# Use-case
---
## 영어 회화 평가 응시

**기본 흐름**
1. 시스템은 평가 주제와 시작 수준 선택 화면을 제공한다.
2. 사용자는 주제와 초급·중급·고급 중 시작 수준을 선택한다.
3. 시스템은 평가 규칙과 종료 조건을 안내한다.
4. 사용자는 ‘평가 시작’을 누른다.
5. 시스템은 선택한 주제와 수준에 맞는 첫 질문을 음성으로 제시한다.
6. 사용자는 음성으로 답변한다.
7. 시스템은 답변을 기록하고, 확인된 능력에 따라 후속 질문을 제시한다.
8. 사용자와 시스템은 충분한 평가 근거가 확보되거나 최대 평가 시간에 도달할 때까지 대화를 반복한다.
9. 시스템은 평가 종료를 안내하고 수집된 답변을 분석한다.
10. 시스템은 최종 수준과 항목별 점수·근거가 포함된 보고서를 제공한다.
11. 사용자는 평가 보고서를 확인한다.

**대안·예외 흐름**
- **사용자가 중도 종료한 경우:** 
	- 시스템은 수집된 답변으로 평가 가능 여부를 판단하고, 잠정 결과 또는 평가 불가를 안내한다.
- **사용자가 평가를 잠시 멈춘 경우:**
	- 시스템은 현재까지의 진행 상태를 저장하고, 재개 허용 시간 안에 마지막 질문과 답변부터 이어갈 수 있게 한다.
- **분석에 실패한 경우:** 
	- 시스템은 평가 기록을 보존하고 분석 재시도 상태를 안내한다.

## 로그인 및 회원가입

**기본 흐름**
1. 시스템은 회원가입 화면을 제공한다.
2. 사용자는 ID, 비밀번호, 비밀번호 확인을 입력한다.
3. 사용자는 ‘가입하기’를 누른다.
4. 시스템은 입력값과 ID 중복 여부를 검증한다.
5. 시스템은 계정을 생성한다.
6. 시스템은 Access JWT와 Refresh Token을 발급한다.
7. 시스템은 사용자를 자동으로 로그인시키고 평가 홈으로 이동시킨다.

**대안·예외 흐름**
- **ID가 이미 사용 중인 경우:** 시스템은 중복을 안내하고 다른 ID 입력을 요청한다.
- **입력값이 형식에 맞지 않는 경우:** 시스템은 해당 항목의 입력 기준을 안내하고 수정을 요청한다.
- **비밀번호 확인이 일치하지 않는 경우:** 시스템은 불일치를 안내하고 재입력을 요청한다.
- **계정 생성에 실패한 경우:** 시스템은 가입 실패를 안내하고 재시도할 수 있도록 한다.
- **계정 생성 후 자동 로그인만 실패한 경우:** 계정을 유지하고 다시 로그인하도록 안내한다.
- **감사 로그** : 감사로그 안찍을 것임.

**관련 규칙**
- ID는 계정 간 중복될 수 없다.
- 비밀번호는 서비스에서 정의한 보안 기준을 충족해야 한다.
- 비밀번호는 평문으로 저장하지 않는다.
- 약관·사용자 동의 기능과 관련 테이블은 이번 범위에서 제외하고 추후 필요할 때 추가한다.
- 인증은 Access JWT로 처리하고 Refresh Token 발급·갱신·폐기를 이번 범위에 포함한다. 유효한 Refresh Token이 있으면 Access Token 만료 후 재로그인 없이 갱신할 수 있다.
- Refresh Token은 DB에 해시만 저장하고 HttpOnly·Secure 쿠키로 전달한다. 갱신 시 같은 행의 해시를 교체하며 최초 만료 시각을 유지한다. 만료·폐기된 토큰이나 비활성 회원의 갱신은 거절한다.
- 로그아웃은 해당 Refresh Token을 폐기하고 인증 쿠키와 클라이언트 Access Token을 삭제한다. 이미 발급된 Access Token은 만료까지 유효할 수 있다.
- 별도 서버 로그인 세션, 기기별 세션 관리, 토큰 회전 이력·재사용 탐지는 제외한다. 상세 저장 구조와 갱신 규칙은 [기본 ERD](../engineering/erd.md)를 따른다.
