
## 기능 범위
| 영역    | WAS 담당 기능                         |
| ----- | --------------------------------- |
| 회원    | 회원가입, 로그인, 로그아웃, 인증 상태 확인, 토큰 갱신 |
| 평가 설정 | 평가 주제 및 시작 수준 조회                  |
| 평가 진행 | 평가 세션 생성, 시작, 답변 접수, 후속 질문 제공, 일시정지·재개, 종료 |
| 입력·재시도 | 입력 오류 안내, AI 분석 재시도                    |
| 평가 분석 | 분석 작업 요청, 처리 상태 관리, 결과 저장         |
| 보고서   | 평가 보고서 및 평가 기록 조회                 |
음성 인식, 질문 생성, 음성 합성, 회화 능력 분석은 별도 AI 처리 서비스와 연동하는 구조를 가정합니다. WAS는 처리 요청과 결과를 관리합니다.

**2일 사내 해커톤에서 영어 회화 평가 흐름을 구현하는 데 집중합니다.** 감사 로그, 약관·사용자 동의, 네트워크 연결 복구, 토큰 회전 이력·재사용 탐지 및 기기별 세션 관리는 이번 범위에서 제외합니다. Refresh Token 발급·갱신·폐기와 갱신 시 해시 교체, 평가 세션 재개와 실패한 AI 분석 재시도는 포함합니다.

## 회원 및 인증 기능
| 기능 ID   | 기능명      | 입력                               | WAS 처리                                                                    | 응답 및 예외                                           |
| ------- | -------- | -------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| AUTH-01 | 회원가입 | ID, 비밀번호, 비밀번호 확인 | 필수값·형식·비밀번호 일치 검증, ID 중복 확인, 비밀번호 해시 처리, 계정 저장, Access JWT·Refresh Token 발급 | 사용자 정보·Access Token 반환, Refresh Token 쿠키 설정. 중복 ID·형식 오류 시 가입 거절 |
| AUTH-02 | 로그인 | ID, 비밀번호 | 입력값·비밀번호 검증, 계정 상태 확인, Access JWT·Refresh Token 발급 | Access Token 반환, Refresh Token 쿠키 설정. 인증 실패 시 동일한 오류 메시지 제공 |
| AUTH-03 | 로그아웃 | Refresh Token 쿠키 | 해당 토큰 폐기, 인증 쿠키 및 클라이언트 Access Token 삭제 | 로그아웃 완료 응답. 이미 만료·폐기된 토큰도 완료 처리 |
| AUTH-04 | 인증 상태 조회 | Access JWT | 서명·만료·클레임 및 계정 상태 확인 | 사용자 기본 정보 반환. 만료·무효 토큰은 인증 오류 반환 |
| AUTH-05 | 토큰 갱신 | Refresh Token 쿠키 | 토큰 해시·만료·폐기 및 회원 상태 검증, 기존 해시 조건의 원자적 교체, 새 Access JWT·Refresh Token 발급 | Access Token 반환, Refresh Token 쿠키 교체. 만료·폐기·무효 토큰 및 비활성 회원은 갱신 거절 |
**처리 규칙**

- ID 중복은 DB의 유일성 제약으로도 방지한다.
- 비밀번호 원문과 비밀번호 확인값은 저장하지 않는다.
- 약관·사용자 동의 항목은 현재 가입 입력 및 저장 대상에서 제외한다.
- 계정 생성 후 자동 로그인만 실패했다면 계정을 유지하고 로그인하도록 안내한다.
- Access Token은 JWT로 발급하며 DB에 저장하지 않는다. Refresh Token은 난수로 생성하고 refresh_token 테이블에 해시·만료·폐기 정보를 저장한다. 원문 토큰은 저장하거나 로그에 기록하지 않는다.
- Refresh Token은 HttpOnly·Secure 쿠키로 전달하며 SameSite 정책과 요청 Origin 검증을 적용한다. 갱신·로그아웃은 POST 요청으로 처리한다.
- 갱신 시 동일 행의 해시를 교체하고 최초 발급·만료 시각을 유지한다. 동시에 들어온 갱신 요청 중 하나만 성공시킨다. 별도 서버 로그인 세션·기기 관리·회전 이력·재사용 탐지는 구현하지 않는다. 토큰 수명은 서버 설정에서 정한다.
- 로그아웃은 해당 Refresh Token을 폐기하고 쿠키 및 클라이언트 Access Token을 삭제한다. Access Token이 만료되어도 로그아웃할 수 있다. 이미 발급된 Access Token은 만료까지 유효할 수 있다.
- 인증 계약은 tRPC의 `auth.signup`, `auth.login`, `auth.logout`, `auth.me`, `auth.refresh`로 노출한다. 상세 저장 구조와 검증 규칙은 [기본 ERD](../engineering/erd.md)를 따른다.


## 3. 평가 설정 및 진행 기능

|기능 ID|기능명|입력|WAS 처리|응답 및 예외|
|---|---|---|---|---|
|EVAL-01|평가 설정 조회|없음|신규 세션에서 선택할 수 있는 활성 회화 상황·대화 범위, 시작 수준, 평가 규칙, 최대 시간 조회|선택 가능한 설정 반환|
|EVAL-02|평가 세션 생성|주제 ID, 시작 수준|인증 확인, 활성 주제와 시작 수준 검증, 선택 주제를 질문 생성 맥락으로 연결한 사용자 소유 세션 생성, 적용할 평가 정책 버전 저장|평가 세션 ID 및 준비 상태 반환|
|EVAL-03|평가 시작|평가 세션 ID|소유권·상태 확인, 시작 시각 기록, 첫 질문 요청, 질문 및 음성 정보 저장|첫 질문과 음성 정보 반환|
|EVAL-04|음성 답변 접수|평가 세션 ID, 질문 ID, 음성 데이터|소유권·진행 상태·파일 조건 검증, 음성 저장, 음성 인식 및 답변 분석 요청|답변 접수 상태 반환|
|EVAL-05|후속 질문 제공|답변 처리 결과|평가 근거 축적, 다음 질문 난이도 결정 요청, 종료 조건 확인|후속 질문 또는 평가 종료 상태 반환|
|EVAL-06|평가 종료|평가 세션 ID, 종료 요청|종료 사유·시각 기록, 추가 답변 접수 차단, 접수된 답변 정리, 분석 작업 생성|종료 및 분석 대기 상태 반환|
|EVAL-07|평가 상태 조회|평가 세션 ID|소유권 확인, 진행·답변 처리·분석 상태 조회|현재 상태와 재개 가능 여부 반환|
|EVAL-08|평가 재개|평가 세션 ID|소유권·일시정지 상태·재개 허용 시간 확인, 마지막 확정 질문과 답변 상태 복원|재개 상태 반환. 허용 시간을 넘긴 세션은 종료 처리|
|EVAL-09|평가 일시정지|평가 세션 ID|소유권·진행 상태 확인, 현재 진행 상태 저장 및 일시정지 시각 기록|일시정지 상태 반환|

평가 세션의 회화 상황·범위(일상·여행·직장)를 선택한다. 주제는 서버의 고정 코드로 정의하고 세션의 topic_code에 저장한다. 개별 질문은 question, 고정 5개 채점 항목은 assessment_criterion_code ENUM으로 관리한다.

**처리 규칙**
- 시작 수준은 `BEGINNER`, `INTERMEDIATE`, `ADVANCED` 중 하나로 제한한다.
- 시작 수준 선택지는 `proficiency_band_code` ENUM 계약에서 제공하고, 초급·중급·고급 표시명은 클라이언트에서 매핑한다.
- 시작 수준은 첫 질문의 난이도에 사용하며 최종 수준을 제한하지 않는다.
- 질문 난이도는 확인된 능력과 평가 근거에 따라 조정한다.
- 평가 중 힌트, 다시 듣기, 표현 설명, 교정 기능은 제공하지 않는다.
- 충분한 평가 근거 확보, 최대 시간 도달, 사용자 종료 요청에 따라 평가를 종료한다.
- 이미 접수된 답변의 처리가 끝난 뒤 최종 분석을 진행한다. 처리 실패 구간은 평가 제한 사항으로 남긴다.
- 종료 판단은 클라이언트 타이머에만 의존하지 않고 서버에서 확인한다.

## 4. 분석 및 보고서 기능
|기능 ID|기능명|입력|WAS 처리|응답 및 예외|
|---|---|---|---|---|
|REPORT-01|분석 작업 실행|종료된 평가 세션 ID|분석 대상 음성·대화 기록 수집, AI 분석 요청, 처리 상태 갱신|분석 완료 또는 실패 상태 저장|
|REPORT-02|평가 결과 저장|AI 분석 결과|결과 형식·점수 범위·근거 발화 참조 검증, 최종 수준 및 항목별 결과 저장|보고서 생성 완료 처리|
|REPORT-03|분석 재시도|실패한 분석 작업|재시도 가능 오류 확인, 정해진 횟수 내 재요청, 중복 결과 저장 방지|재시도 상태 또는 최종 실패 상태|
|REPORT-04|보고서 조회|평가 세션 ID|인증·소유권·분석 완료 여부 확인|최종 수준, 항목별 점수, 근거, 개선 사항 반환|
|REPORT-05|평가 기록 조회|페이지 정보|사용자 본인의 평가 기록 조회|주제, 평가 일시, 상태, 최종 수준 목록 반환|
**결과 규칙**
- 최종 수준은 초급·중급·고급 각각의 하·중·상, 총 9개로 고정한다. 저장 코드는 `BEGINNER_LOW`부터 `ADVANCED_HIGH`까지이며, 전체 값은 [ERD의 고정 평가 항목과 수준](../engineering/erd.md#enum-허용값)에 정의한다.
- 결과 판정 상태는 `확정`, `잠정`, `평가 불가`로 구분한다. AI가 수준을 판단할 수 있고 유효 답변 5개 이상·5개 항목 채점 가능이면 확정, 기준 미달은 잠정, 수준 판단 불가는 평가 불가다.
- 평가 항목은 어휘(`VOCABULARY`), 문법(`GRAMMAR`), 발음(`PRONUNCIATION`), 유창성(`FLUENCY`), 답변 적절성(`RELEVANCE`)의 5개로 고정한다.
- 항목별 점수는 0~100 정수다. 최종 수준은 점수 평균 환산이 아닌 고정 수준 설명에 따른 AI 판단을 사용한다. 근거 부족은 NULL과 사유를 저장하고 ‘평가 데이터 부족’으로 표시한다.
- 원본 음성 검토로 전사 사용 가능 여부를 확인하고 인식이 불확실한 답변은 해당 항목의 평가에서 제외한다.
- 항목마다 최대 3개 실제 답변을 근거로 연결하며 해당 답변의 원본 녹음 전체를 조회·재생한다. 질문·전사·음성·길이는 관계에서 조회한다.
- 표현 수정과 개선 피드백은 평가 종료 후 보고서에서만 제공한다.

## 5. 평가 상태 관리
|상태|의미|다음 상태|
|---|---|---|
|`READY`|평가 설정 완료, 시작 전|`IN_PROGRESS`|
|`IN_PROGRESS`|질문·답변 진행 중|`PAUSED`, `ENDING`|
|`PAUSED`|사용자가 평가를 잠시 멈춤|`IN_PROGRESS`, `ENDING`|
|`ENDING`|종료 확정 후 접수된 답변 정리 중|`ANALYSIS_PENDING`|
|`ANALYSIS_PENDING`|분석 작업 대기|`ANALYZING`|
|`ANALYZING`|분석 진행 중|`COMPLETED`, `ANALYSIS_FAILED`|
|`COMPLETED`|확정·잠정·평가 불가 결과 생성 완료|없음|
|`ANALYSIS_FAILED`|기술적 오류로 분석 실패|`ANALYSIS_PENDING`|
‘평가 데이터 부족’은 시스템 장애와 구분합니다. 분석이 정상적으로 끝났어도 근거가 부족하면 `COMPLETED` 상태에서 ‘평가 불가’ 결과를 저장할 수 있습니다.

## 구현된 tRPC API

모든 기능은 tRPC → Nest Controller → 인바운드 포트 구조를 따른다. 분석 단계·오류·시도 횟수는 Redis/BullMQ에서 관리하고 별도 운영 이력 테이블을 만들지 않는다. 현재 수준은 최신 확정 보고서에서 조회한다.

세션 생성 요청에는 FE가 생성한 evaluationId를 포함해 중복 생성을 방지한다. 상세 동작과 실제 검증 범위는 [회화 구현 결과](../engineering/conversation_implementation.md), [보고서 구현 결과](../engineering/report_implementation.md)를 따른다.
